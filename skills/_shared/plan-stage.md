# Internal PLAN procedure

Explore the agreed specification, current code, architecture and test seams. Return
the complete structured plan with small tasks, meaningful acceptance criteria and
an acyclic dependency graph. Preserve every runner-supplied agreed field, including
verification capabilities, setup, protected inputs and repair policy.

When the seed has direct workflow metadata, return exactly one independent task with
explicit scope.paths covering implementation and meaningful regression tests. Preserve
the original Issue and separate push/PR permissions. Do not add integration steps.

This stage runs read-only. Return the plan through the structured result. The CLI
owns the draft documents and approval workflow. Do not invoke feature planning,
drafting, approval, start, publication or any other orchestration command.

Return blocked when an unresolved choice prevents a valid plan. Do not infer new
permissions from a requested outcome.
